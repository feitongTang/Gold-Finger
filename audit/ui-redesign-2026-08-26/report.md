# Gold-Finger UI 系统重构审计

## 审计范围

- 产品：Gold-Finger 本地单用户月度财务复盘 MVP。
- 核心任务：查看本月结果、切换历史月份、读取趋势、更新月度记录、导出与恢复备份。
- 目标：Desktop-first（1280–1920px），建立克制、自然、精准、长期可维护的视觉系统，并完整移除用户主题色切换能力。
- 证据：本次运行中采集的 1440×900 与 1920×1080 页面截图，以及当前组件与样式源码。

## 审计步骤

1. 空月份概览 — 功能健康，视觉层级偏重。空状态可理解，主行动明确；但大面积空白被完整圆角面板包裹，标题、月份切换、空状态和 CTA 被切成多个视觉层。
2. 已保存月份概览 — 信息完整，扫描成本偏高。净资产是明确主指标；但跨月一致性、资金分配、资产结构和组合分类均使用独立容器、边框或背景，页面呈现“面板套面板”。
3. 历史趋势 — 数据表达健康，组件感过强。图表结构、图例和切换状态清楚；两个图表都被大圆角卡片包围，弱化了内容连续性并拉长页面。
4. 月度录入 — 交互基础较好，表单节奏偏机械。分步编号、标签、单位、错误结构和键盘语义已有良好基础；但整条步骤轴、大区块边界、每行基金卡片和大面积强调色会让长表单显得沉重。
5. 数据安全 — 功能清晰，主次关系不够准确。导出应是主要动作，恢复应是低频高风险动作；当前两栏卡片与大按钮让两者视觉权重接近。
6. 1920px 概览 — 宽度控制健康。75rem 容器避免了内容无限拉伸；但背景渐变、整页大圆角表面和 header 主题色圆点在大屏上更突出，视觉噪声随空白同步放大。

## 已有优势

- 核心任务闭环完整，业务信息没有被装饰性 UI 掩盖。
- 页面已有稳定的最大宽度，并未在 1920px 无限拉伸。
- 净资产、负数、资产构成、趋势图等关键数据具备清晰语义。
- 表单的 label、error、aria-describedby、focus 定位和成功回流逻辑较扎实。
- 图表包含可访问名称与可展开数据表，不仅依赖视觉曲线。
- 本地数据安全与危险操作确认已进入产品结构。

## 主要问题

### 结构问题

- 单页同时承担结果、趋势、录入和备份，靠一连串大型圆角容器分区，页面长度和分组层级都偏重。
- `globals.css` 已增长到 2573 行；存在 129 条 border、73 条 background、35 条 radius 与 14 条 shadow 声明，视觉规则集中但缺少明确的 token 层与组件层边界。
- 页面内部广泛重复“标题 + 辅助说明 + 带边界内容块”，文字层级尚未充分承担分组工作。
- 同一类动作在结果区与录入区重复出现，增加页面噪声。

### 视觉问题

- 7 套主题使品牌气质不稳定，header 中的色板圆点反而成为全页最抢眼的元素。
- 渐变背景、半透明表面、blur、glass shadow、圆角大面板同时出现，整体更接近轻拟物 dashboard，而非克制的 editorial finance 工具。
- Accent 同时染色标题、按钮、图表、步骤编号、标签与辅助背景，未形成 90% neutral / 10% accent 的标点关系。
- Card、border 与 surface difference 的使用重叠，经常用三种方式同时表达同一层级。
- 部分辅助文本过淡且字号偏小；视觉上能读，但仍需在实施后做对比度与缩放测试。

### 体验问题

- 月份切换位于大面板内部第二行，与页面标题和主指标距离较远，用户先看到结果再理解当前月份。
- 跨月一致性是复核信息，却占据与核心财务数据相近的视觉面积。
- 空月份仍展示完整趋势和后续区域，空状态主行动与下方“新建数据”重复。
- 数据安全区中恢复操作与导出操作并列，未充分体现使用频率和风险差异。
- Header 在移除主题选择后无需添加替代物；当前左侧品牌与语境本身已足以保持平衡。

## 可访问性风险与证据边界

- 截图显示部分 metadata 与辅助说明对比度偏低，需以最终 token 进行 WCAG 对比度计算。
- 当前 focus ring 结构存在，表单错误也能定位；仍需在重构后完整走查 Tab 顺序、图表切换、展开区和文件输入。
- 仅凭截图不能确认屏幕阅读器输出、200% 缩放重排、所有 hover/focus/disabled 状态或 `prefers-reduced-motion` 行为。

## 三种重构方向

### A. Warm Editorial Finance（推荐）

温暖纸张色背景、墨色正文、深朱砂固定 Accent。以排版、细分隔线、数字对齐和节奏建立高级感；仅保留结果总览与真正独立交互对象的轻表面。它最贴合“安静但不无聊”，也能让 Gold-Finger 形成自己的品牌记忆。

### B. Natural Ledger

石灰白与低饱和深绿，像精装账册与现代木作空间。更自然、更 MUJI，但金融产品容易显得过于生活方式化，重要负数与主行动之间的色彩关系也更难控制。

### C. Mineral Precision

冷灰白与固定钴蓝，像精密仪器和现代建筑图纸。清晰、理性、易做数据可视化，但与当前产品已有的温暖气质距离较远，也更容易落入常见 SaaS dashboard 观感。

## 推荐方案

- 固定主题：Warm Editorial Finance。
- 固定 Accent：深朱砂，用于主按钮、选择态、焦点和极少数关键数据；负数继续使用语义红，但与品牌朱砂通过明度和用途区分。
- 全局背景：温暖 off-white；主要内容默认直接落在页面背景上，只有需要明确边界的交互区使用 surface。
- Header：移除所有主题入口、Local Storage、启动脚本和相关测试；保留紧凑品牌与“月度财务复盘”语境，不增加占位动作。
- 页面：将月份切换纳入页面级标题行；本月净资产成为唯一首屏视觉锚点；跨月一致性降级为紧凑复核提示；资金与资产指标采用表格式网格而非卡片组。
- 趋势：保留两个图表，但去除外层大卡片感，以 section、标题、图例和细分隔线组织。
- 表单：保留现有业务顺序与错误处理；用更轻的 section divider 取代完整步骤轨道与层层表面；字段和基金行统一控制高度、边框、focus 与错误状态。
- 数据安全：导出为明确主行动；恢复作为次要危险操作放入低频区域，避免和日常更新争夺注意力。
- Token：建立颜色、字体、间距、圆角、阴影、动效的单一 CSS variable 层；组件只消费语义 token，不再保留多主题分支。

## 验收重点

- 1280、1366、1440、1512、1600、1920px 下无横向溢出，内容宽度与留白稳定。
- Header 中不存在主题切换入口，用户无法切换 Accent，相关状态与存储代码全部删除。
- 页面每个区域最多 1–2 个视觉重点；删除不承担信息或交互职责的 card、border、background、icon 与 badge。
- 所有按钮、输入、选择、展开、危险操作具备一致的 hover、active、focus、disabled 与 loading 状态。
- 表单行为、数据流、路由、持久化与计算结果保持不变。
- 格式、lint、类型、测试和生产构建全部通过；完成后进行浏览器尺寸与交互一致性复核。
