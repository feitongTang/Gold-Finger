# Task 2：首次使用与月度更新录入设计

## 目标与范围

在首页提供一个连续的月度录入流程，让本地单用户完成首次资产录入，并在以后按月份读取和更新同一份快照。流程覆盖收入、支出、投资投入、三类现金、基金名称/固定分类/市值/累计投入和花呗余额。

本任务只负责录入、校验、保存与编辑反馈。月度结余、净资产和资产结构等复盘结果留给 Task 3，不在提交后提前实现。

## 用户流程与界面

首页改为单页分区表单，依次包含：

1. 月份与现金流。
2. 三类现金资产。
3. 可增删的基金列表。
4. 花呗负债与提交操作。

月份默认当前自然月。用户切换月份后，页面读取该月份快照；存在时回填并显示“更新”，不存在时显示空表单和“首次记录”或“新建”。为避免切换月份时丢失尚未提交的内容，月份选择通过明确的“载入该月份”提交来导航，而不在选择变化时自动跳转。

金额输入统一使用人民币元，允许最多两位小数；数据库仍保存整数分。所有金额必须非负，必填金额允许填写 `0`。基金名称去除首尾空格后必须非空，分类只能来自现有固定分类。基金列表允许为空。

桌面端使用宽度受控的双列字段布局，基金每行按名称、分类、市值、累计投入排列；手机端改为单列卡片，避免横向滚动。每个输入都有可见标签，错误通过 `aria-describedby` 关联，提交结果使用 `aria-live`，添加和删除基金均使用原生按钮，键盘可完整操作。

## 模块边界与数据流

- `src/app/page.tsx` 保持为 Server Component：解析月份查询参数，在服务端读取数据库，并把可序列化的初始值交给表单。
- `src/features/monthly-snapshots/monthly-snapshot-form.tsx` 是最小客户端交互边界：管理基金行增删、`useActionState` 的提交状态和待处理反馈，不导入数据库模块。
- `src/features/monthly-snapshots/actions.ts` 定义 Server Action：把不可信 `FormData` 交给纯解析器，校验通过后调用仓储；按月份是否存在选择 `create` 或 `update`，成功后刷新当前页面数据。
- `src/features/monthly-snapshots/form-data.ts` 是纯 TypeScript：负责元转分、月份、固定分类和动态基金行的解析及字段错误映射，可独立测试。
- `src/db/client.ts` 增加惰性的应用数据库访问入口，并确保应用数据库在首次使用时执行已有迁移。测试仍可直接创建内存数据库，不改变现有仓储模式。

URL 使用 `?month=YYYY-MM` 表示当前编辑月份，使重新加载和浏览器前进/后退保持一致。页面读取失败交给路由级 `error.tsx`，提供重试按钮；导航读取期间由 `loading.tsx` 提供有意义的表单骨架。

## 错误处理

浏览器原生约束负责基础体验，Server Action 始终重复完整校验，不能依赖客户端数据可信。

校验失败时不写数据库，返回字段级错误和通用提示；表单保留浏览器中已输入的数据。持久化异常返回可恢复的通用错误，不向界面暴露 SQLite 细节。成功时返回明确提示，并触发当前路径重新读取，使随后刷新可看到保存值。

基金动态字段使用稳定的客户端行标识，但提交数据只使用连续索引；删除一行不会影响其他基金内容。重复提交时禁用提交按钮，避免同一客户端连续写入。

## 测试与验证

按 TDD 先为纯表单解析器增加测试，覆盖：

- 正常元金额转换为整数分，包括两位小数。
- 非法月份、负数、超过两位小数和非数字输入返回对应字段错误。
- 基金为空合法；基金名称为空或分类不在固定列表时失败。
- 多个基金行被完整解析且顺序保留。

再为保存用例增加临时 SQLite 集成测试，证明同一入口会创建新月份、更新已有月份，并在校验失败时保持原数据。UI 不增加新的测试框架；通过构建、桌面与手机宽度的浏览器人工检查验证回填、增删基金、错误、待处理状态、溢出、键盘和基本可访问性。

完成前运行 `npm run format:check`、`npm run lint`、`npm run typecheck`、`npm test` 和 `npm run build`，检查 `git diff` 后将 Task 2 标为 Done。
